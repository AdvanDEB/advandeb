### New items

**C19 — Elicitation frontend and API disagree (P0 for the methods work).**
Verified 2026-10-28. As things stand, experts cannot complete the elicitation
flows from the browser:
- **Enrolment.** `EnrolmentView` sends `full_name` / `consent_acknowledgement`;
  the API requires `name` / `consent`, so the request gets a 422.
- **Calibration answers.** `CalibrationFlow` posts to
  `/elicitation/calibration/answer`, which does not exist. The route is
  `/calibration/decide`, with a different payload.
- **Calibration status.** The view reads `required/complete/passed`; the API
  returns `total/completed/correct/done`.
- **Admin decisions.** `AdminExpertsView` sends `{decision}`; the API expects
  `{approve: bool}`. The view also reads several statistics fields the API
  does not return.
- **Evidence task.** The UI has no evidence-scoring task, yet that task leads
  the queue.

The server-side rules (tiers, calibration gate) hold regardless.
Detail: `docs/ELICITATION.md`.

**C20 — MongoDB is bound to all interfaces on the production host.**
`mongod --bind_ip_all` runs in a container from the cadapti project's Docker
Compose, listening on `0.0.0.0:27017` and `[::]:27017`. Everything else
except the backend is loopback-only. Docker-published ports can bypass
host-firewall rules. Bind it to loopback, or confirm it is unreachable from
outside, and record which.

**C21 — Production data protection.**
In September a verification script dropped production `advandeb.documents`
(`STORAGE-CONTRACT.md` §2a). Since then:
- **Done:** `app/backend/app/core/dbguard.py` refuses non-scratch database
  names in guarded code, and `scripts/restore_documents_from_arango.py`
  exists.
- **Not yet merged on `main`:** scheduled backups and a backup-age guard on
  the KB reset.
- **Still unguarded:** `app/backend/tests/verify_*.py` do not use `dbguard`,
  and one of them still uses `setdefault`.

**C24 — Two stylized-fact matchers.**
`app/backend/app/kb/pipeline.py:_match_sfs` (Mongo) and
`advandeb_kb/services/sf_matcher_service.py` (Arango) do the same job with
different semantics. On a classification failure, the Mongo path falls back to
`supports @ 0.4` for every candidate. That fabricates support edges. Retire
it or align it before any measurement of link quality. This is prerequisite
P5 in `advandeb_methods/docs/04-integration-plan.md`.

**C25 — `external_contributor` is excluded only in the frontend (security).**
The role is meant to exclude documents, chat, the knowledge base, graph and
models, because some curated material is licensed full text that cannot leave
the project. The exclusion lives only in the Vue router
(`router/index.ts`) and the sidebar. No backend dependency checks for the
role, so its token can call every route that needs only `get_current_user`.
That includes `/api/chat` (on the shared default key), `/api/kb/documents`,
`/api/facts`, `/api/graph/provenance/…` and `/api/graph/chunk/{id}/context`.

Fix this before approving any outside expert as a contributor: add a
dependency that rejects external-only users on every non-elicitation router,
and test it.

### The elicitation direction (from `advandeb_methods`)

The methods repository (`~/dev/advandeb_methods`; `STATUS.md`,
`docs/02`–`docs/10`) is where the consensus method is specified. AdvanDEB is
where it ships.

**What it builds.** A local, continuously running panel of open-weight models
scores how well the literature supports each of **1,262 DEB stylized facts**.
A **panel of human DEB experts** does the same task. Neither panel is ground
truth. The paper reports the consensus method and the human-validation
protocol as co-equal contributions, plus an atlas of all 1,262 facts. The
target venue is the next DEB symposium, not a journal deadline.

**The critical path is the human ceiling.** The machine panel's first sweep
reached Krippendorff's α = 0.431, and 0.259 on `contradicts`. That number is
uninterpretable until experts scoring the *same* evidence produce their own
agreement figure. Hence:
- the evidence-scoring task leads the queue (`5ceb4fa`);
- the `deb` corpus items take the full panel (`ELICITATION_HUMAN_PANEL_SIZE`,
  default 5).

**Decisions the platform must respect** (decided in the methods repo; do not
reopen here):
- two tiers, **panel** and **contributor**, never pooled;
- expert-asserted DOIs are a **third score**, never added to the machine's;
- at least three adjudicators;
- local open-weight models only for the consensus daemon;
- the scales stay 1–3.

**Platform prerequisites** (`advandeb_methods/docs/04` §2), mapped to this
plan:

| Prerequisite | Platform item | State |
|---|---|---|
| P1 durable provenance | C3 | open |
| P2 review persistence | SYSTEM-OVERVIEW §8 | open |
| P3 wire capabilities | — | **done** (`sf_elicitation`) |
| P4 CI honesty | C1 | open, worse |
| P5 one SF matcher | C24 | open |

**Next steps, in order** (methods `STATUS.md` §7, plus this audit):
1. Fix C19, so experts can actually use the UI.
2. Make sure the running backend is current (C23).
3. Import the 186 frozen evidence sets and build the evidence queue.
4. Experts score; the human ceiling falls out.
5. Then calibration thresholds and the full-collection atlas.

## 2. P0 — Correctness we are currently blind to

### C1 — The CI knowledge-builder job tests nothing *(new)*

`.github/workflows/ci.yml`:

```yaml
- name: Pytest -- knowledge-builder
  working-directory: knowledge-builder
  run: pytest -x -q tests/ || true
```

Two independent faults, and they mask each other:

1. `|| true` swallows every failure.
2. It runs `knowledge-builder/tests/`, but the KB test module that is
   actually broken lives in the **repo-root** `tests/` directory — so CI
   never even loads it.

**Fix:** drop `|| true`; add the repo-root `tests/` directory to the job (or
consolidate the two test roots — see C2). Accept only when a deliberately
broken test causes a red build.

**Why P0:** every other quality claim in this document rests on CI being
honest. It currently is not.

### C2 — `tests/test_layout_algorithms.py` does not import *(5)*

*(2026-10-28: fixed in `0768b04`.)*

```
ModuleNotFoundError: No module named 'advandeb_kb.services.visualization_service'
```

Same failure class the May review flagged for `test_graph_service.py` — a
test outliving the module it covers. The layout code now lives in
`graph_query_layouts.py` (part of the `graph_query_service` split).

**Fix:** rewrite the module against `graph_query_layouts`, or delete it if
the layout algorithms are covered elsewhere. Decide which; do not leave it.

**Note:** there are two test roots (`tests/` and `knowledge-builder/tests/`)
with no stated division of labour. Worth collapsing while fixing C1.

### C3 — `provenance_traces` is empty *(new)*

Arango `provenance_traces` holds **0 documents**, yet `provenance_service.py`
exists in the backend and the provenance trail panel is listed as shipped.

Either provenance is persisted somewhere else (in which case the empty
collection is dead schema and should be dropped), or the trail panel is
rendering something reconstructed on the fly and nothing is durable. These
have very different implications for a system whose founding goal was
"eliminate hallucinations … with full provenance tracking."

**Fix:** determine which. This is an investigation, not a code change —
timebox it, then file the real item.

### C6 — No anonymous read-only path *(10, 34)*

`SYSTEM-OVERVIEW.md` describes a `Knowledge Explorator` role with read-only
access to published knowledge. In the code, `"anonymous"` appears only as a
websocket session-id fallback (`api/routes/ws.py`). There is no anonymous

This is the **strategic decision of the quarter**, not a task. Two coherent
answers:

  size — non-trivial at 3.9M documents.
- **(b) Commit to closed.** Remove the read-only role from the documentation
  and stop implying a public KB.

Doing neither is the current state and is the worst of the three. Decide
before building C5, because the answer changes what the landing page says.

### C9 — The storage contract is unwritten *(24)*

Three stores and two Mongo databases hold overlapping entities:

| Entity | Mongo `advandeb` | Mongo `..._kb` | Arango `advandeb_kb` |
|---|---|---|---|
| documents | 1,695 | 1,305 | 3,899,789 |
| facts | 28,309 | 63,709 | 109,395 |
| stylized_facts | 1,236 | 1,236 | 1,236 |
| graph nodes | 49,700 | 102,060 | — |
| graph edges | 70,724 | 155,397 | 31,311 (`sf_support`) |

The numbers disagree in every row but one. Some of this is certainly

**Why this matters more than it looks:** every future "why does the graph

`app/backend/app/main.py:65`. Singleton task election still uses a heuristic

### C14 — Token storage hardening *(28)*

Access token in memory, refresh token in an httpOnly + Secure +
SameSite=Strict cookie, with the matching CSP documented. Unchanged from May;
still open. Lower priority now that `/logout` revocation and rate limiting
have landed, but the XSS exposure is real.

### C15 — Async ArangoDB driver / thread-pool audit *(26)*

`HybridRetrievalService` runs sync Arango calls through a 4-worker
`ThreadPoolExecutor`. At 3.9M documents this is a plausible throughput
ceiling. Measure before rewriting — this may be fine, and the measurement is
cheap.

### C16 — Open-source decision *(35)*

*(2026-10-28: the premise below is wrong — the repository is public on GitHub.
See §0.)*

READMEs reference a fork-and-PR workflow with no public repo. Same class of

### C18 — Finish or formally abandon the Mongo→Arango migration *(new)*

`app/backend/app/core/config.py:61`:

```python
# Transitional: KB_DB_NAME used during MongoDB→ArangoDB migration. Remove after migration.
KB_DB_NAME: str = "advandeb_knowledge_builder_kb"
```

That comment is the explanation for every count mismatch in C9. The
`advandeb_knowledge_builder_kb` database is the **previous generation** of the
knowledge store, mid-migration to ArangoDB — and it is still written to by the
ingestion workflow, the visualization artifact store, and user submissions.

`core/database.py:17` describes it as "ingestion workflow state only." That is
no longer accurate.

**This is the largest untracked piece of work in the system.** It is not on the
old plan at all, because in May the migration was in flight (`b1999819`,
"pre-review baseline (Mongo→Arango migration WIP)"). It has now been in flight
for three months, and the half-state is what makes the system hard to reason
about.

**Fix:** two honest options.
- **Complete the cutover** — migrate the remaining writers, drop the database,
  remove `KB_DB_NAME`, collapse the two `Settings` objects.
- **Formally promote it** — give it a documented role and an owner, and rewrite
  the comment. Only defensible if there is a reason it must stay.

Doing neither is the current state, and it compounds: every new feature that
touches ingestion or visualization has to pick a database, and there is no rule
to pick by beyond `docs/STORAGE-CONTRACT.md`, which describes the mess rather
than resolving it.

### C17 — Design system *(36)*

Element Plus and Tailwind tokens coexist with hand-rolled hex codes in
`LoginView`/`HomeView`. Pick one. Best done immediately before C5, since the
landing page is new surface that will otherwise add a fourth style.
